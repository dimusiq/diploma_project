# Идеи по улучшению проекта Nebardak

Сводка того, что можно добавить, чтобы усилить функционал склада (поступления → склад → отгрузка) и общее качество приложения.

---

## Уже реализовано (кратко)

- Расширение Item: `quantity`, `sku`, `barcode`, `unit`, `category_id`, `expires_at`, `location`, `created_at`.
- Справочник категорий (CRUD, иерархия через `parent_id`), выбор категории в формах и фильтрах.
- История изменений: `ItemHistory`, API `GET /items/{id}/history`, отображение в UI.
- Роли: admin, manager, warehouse, viewer; проверки прав (кто видит чужие items, кто меняет статус).
- Поиск и фильтры: `search`, `category_id`, пагинация на Поступлениях, Складе, Отгрузке.
- Короткий ID (ShortId) в таблицах с подсказкой полного UUID.
- Дашборд: карточки, ссылки на разделы, последние поступления, графики (статусы, топ владельцев).
- Главная = Дашборд (объединено).
- Колонка «Категория» в таблицах товаров.
- Печать: PDF накладная (с логотипом, кириллица), этикетка со штрихкодом; кнопки на странице отгрузки и в меню товара.
- Массовый выбор товаров: чекбоксы, «Печать накладной» по выбранным, «Переместить» (диалог выбора статуса).

## 1. Домен и модели данных

### 1.1 Расширение модели Item

Сейчас: `title`, `description`, `status`, `owner_id`.

Имеет смысл добавить (по необходимости):

| Поле            | Тип     | Назначение                          |
|-----------------|---------|-------------------------------------|
| `quantity`      | int     | Количество (сейчас по сути 1 единица на запись) |
| `sku`           | str     | Артикул для поиска и отчётов        |
| `barcode`       | str     | Штрихкод для приёма/отгрузки        |
| `unit`          | str     | Единица измерения (шт, кг, л, упак.) |
| `category_id`   | FK      | Связь со справочником категорий     |
| `expires_at`    | date    | Срок годности (опционально)          |
| `location`      | str     | Ячейка/зона склада                  |
| `created_at`    | datetime| Дата поступления (для отчётов)     |

Это потребует миграций Alembic и обновления API/форм.

### 1.2 Справочник категорий

- Модель `Category` (название, родитель для иерархии).
- В `Item` — `category_id` (nullable).
- В API: CRUD категорий, в формах — выбор категории при создании/редактировании.

### 1.3 История изменений (audit log)

- Отдельная таблица `ItemHistory` или общий `AuditLog`: кто, когда, какое поле, старое/новое значение.
- Особенно полезно для `status` и `quantity`: кто и когда переместил «на склад» или «в отгрузку».
- API: `GET /items/{id}/history` (и опционально общий лог для админов).

## 2. Бизнес-логика и API

### 2.1 Валидация переходов по статусам

Сейчас в `ItemActionsMenu` можно перевести в любой из `incoming` / `warehouse` / `shipment`.

Логичнее ограничить:

- `incoming` → `warehouse` (принято на склад)
- `warehouse` → `shipment` (подготовлено к отгрузке)
- `shipment` → «отгружено» (новый статус `shipped` или архив) — опционально

Реализация: на бэкенде в `update_item` проверять допустимый переход; на фронте в меню показывать только разрешённые варианты.

### 2.2 Поиск и фильтрация

В `read_items` уже есть `status`. Имеет смысл добавить:

- `search` — поиск по `title`, `description`, `sku`, `barcode` (ILIKE или full-text).
- `owner_id` — для админов.
- `category_id`, `created_at_from`, `created_at_to` — при появлении полей.

На фронте — форма фильтров над таблицами (items, warehouse, shipment).

### 2.3 Экспорт (Excel/CSV)

- Endpoint `GET /api/v1/items/export?format=csv| xlsx&status=...&search=...`.
- На фронте — кнопка «Выгрузить» на страницах списков и, при необходимости, на дашборде.

### 2.4 Пагинация в API

Уже есть `skip`/`limit`. Можно добавить cursor-based пагинацию для больших объёмов или оставить offset — в зависимости от масштаба.

## 3. Frontend

### 3.1 Пагинация на «Склад» и «Отгрузка»

Сейчас в `warehouse.tsx` и `shipment.tsx` используется `page = 1` без `onPageChange` и без `search`.

Сделать по аналогии с `items.tsx`:

- `validateSearch` с `page`;
- `PaginationRoot` с `onPageChange` и `setPage` через `navigate({ search: { page } })`;
- `getItemsQueryOptions({ page })` с корректным `skip`.

### 3.2 Поиск и фильтры в UI

- Поле поиска (и при наличии — фильтр по категории, дате) над таблицами.
- Передавать `search`, `status` (уже есть на warehouse/shipment), `category_id` и т.п. в `readItems`.

### 3.3 Отображение ID

- Вместо полного UUID — короткий вариант, например последние 8 символов, с `Tooltip` или `title` с полным ID по ховеру.
- Упростит чтение таблиц и переписку.

### 3.4 Подтверждение при смене статуса

Перед `move.mutate(status)` показывать диалог:

- «Переместить «{title}» на склад?» с «Отмена» / «Переместить».
- Аналогично для «В отгрузку» и т.д.

### 3.5 Кнопка «Добавить» на «Склад» и «Отгрузка»

Сейчас `AddItem` только на «Поступления».

Варианты:

- Оставить добавление только в поступления (логично по потоку).
- Или на «Склад»/«Отгрузка» — вызов того же `AddItem` с подсказкой, что по умолчанию статус будет `warehouse`/`shipment` (если решите разрешить создание не из incoming).

### 3.6 Улучшение главной страницы

Сейчас приветствие и «Добро пожаловать».

Можно добавить:

- Блок «Последние поступления» (например, 5 последних items с `status=incoming` или по `created_at`).
- Блок «В отгрузке» (количество или список).
- Краткие ссылки на «Поступления», «Склад», «Отгрузка».

## Что добавить или улучшить дальше (актуальный список)

### Бизнес-логика

- **Валидация переходов по статусам** — на бэкенде в `update_item` разрешить только: `incoming` → `warehouse` → `shipment`; опционально ввести статус `shipped` (отгружено) и переход `shipment` → `shipped`. На фронте в меню и в диалоге «Переместить» показывать только допустимые целевые статусы.
- **Подтверждение при смене статуса** — перед перемещением одного товара из меню показывать диалог: «Переместить «{название}» на склад?» (Отмена / Переместить). Для массового «Переместить» диалог уже есть.
- **Статус «Отгружено»** — добавить `shipped`, убрать такие позиции из активных списков или вынести в отдельный раздел/архив.

### Экспорт и отчёты

- **Экспорт в CSV/Excel** — endpoint `GET /api/v1/items/export?format=csv|xlsx&status=...&search=...`; на фронте кнопка «Выгрузить» над таблицами (Поступления, Склад, Отгрузка) и/или на дашборде.
- **Тренды на дашборде** — график поступлений и отгрузок по дням/неделям за период; endpoint вида `GET /api/v1/dashboard/trends?from=&to=&group_by=day|week`.

### Дашборд

- **Разделение карточек** — сейчас две карточки могут дублировать «склад». Чётко разделить: «Поступления» (incoming), «На складе» (warehouse), «В отгрузке» (shipment), при появлении статуса — «Отгружено» (shipped).

### Удобство и UX

- **Сортировка таблиц** — клик по заголовку: сортировка по названию, дате создания, количеству и т.д. (бэкенд: `order_by`, фронт: заголовки с иконкой направления).
- **Фильтр по дате** — в API и UI: `created_at_from`, `created_at_to` для отчётов и списков.
- **Копирование товара** — действие «Дублировать» в меню товара: создание копии с тем же полями (без истории), с возможностью сразу отредактировать.
- **Массовое редактирование** — для выбранных чекбоксами товаров: сменить категорию или единицу измерения одним действием (диалог + один запрос или пакет обновлений).

### Качество и надёжность

- **E2E-тесты (Playwright)** — сценарии: логин → создание товара → переход на склад → в отгрузку; проверка дашборда; печать накладной по выбранным; сброс пароля.
- **Rate limiting** — ограничение частоты запросов к `/login`, к API (по IP или user_id), например через `slowapi` или middleware.
- **Бэкапы БД** — скрипт (cron) с `pg_dump` и выносом в object storage или отдельный диск; описать в DOCKER.md / deployment.md.
- **Структурированные логи** — request_id, user_id, path, status_code; при необходимости метрики (Prometheus) для latency и ошибок.

### Дополнительно

- **Уведомления по email** — при массовой отгрузке или критичных действиях отправка письма ответственному (расширение текущей email-инфраструктуры).
- **Поиск по штрихкоду** — поле «Сканировать штрихкод» на страницах списков: ввод/скан → переход к товару или открытие карточки.
- **PWA и офлайн** — Service Worker, manifest.json, кеширование справочников и своих товаров для работы при нестабильной сети (после стабилизации основного функционала).
- **Уникальность штрихкода** — при наличии поля проверять уникальность в рамках склада/системы и показывать предупреждение при дубликате.

## UX/UI: что добавить для улучшения дизайна

### Приложение в целом

- **Единый стиль загрузки** — скелетоны (Skeleton) или спиннеры в одном стиле на всех страницах (списки, дашборд, 3D). Сейчас 3D: текст «Загрузка 3D…»; списки — согласовать с Chakra `Skeleton`.
- **Пустые состояния (empty state)** — когда в таблице нет товаров или фильтр ничего не нашёл: иконка, короткий текст и кнопка действия (например «Добавить товар» или «Сбросить фильтры»). Уже есть частично; унифицировать.
- **Хлебные крошки (breadcrumbs)** — на вложенных страницах (например Склад → Цифровой двойник) для навигации «назад» и понимания контекста.
- **Подсказки и туториал** — на дашборде и 3D: краткий текст или tooltip при первом заходе («Клик по ячейке — информация», «Колёсико — zoom»). Опционально: кнопка «Показать подсказки» в шапке 3D.
- **Консистентность кнопок и действий** — основные действия (Добавить, Сохранить, Печать) выделять цветом (ui.main); вторичные — outline или ghost. Единые иконки для однотипных действий (FiPlus, FiEdit, FiTrash и т.д.).
- **Доступность (a11y)** — фокус при открытии модалок, закрытие по Escape, `aria-label` у иконок, достаточный контраст текста (уже частично через Chakra).
- **Адаптивность** — на мобильных: бургер-меню сайдбара, таблицы с горизонтальным скроллом или карточный вид на маленьких экранах; 3D — полноэкранный режим или предупреждение «Лучше на десктопе».

### 3D склад в частности

- **Легенда цветов** — небольшая панель в углу 3D (или под заголовком страницы): «Пусто», «Занято», «Срок истекает», «Выбрано». Так пользователь сразу понимает значения цветов и мигания.
- **Подсказка управления** — под канвасом или в тултипе: «Вращение: ЛКМ, Zoom: колёсико, Панорама: ПКМ или Shift+ЛКМ. Клик по ячейке — информация.» Снижает вопросы новичков.
- **Кнопка «Сбросить камеру»** — вернуть вид по умолчанию (как при первой загрузке), если пользователь «заблудился» в сцене. Можно разместить поверх канваса в углу.
- **Закрытие попапа по Escape** — при открытом всплывающем окне ячейки нажатие Escape сбрасывает выбор (как клик по пустому месту). Удобно с клавиатуры.
- **Ссылка «Открыть карточку товара»** — в попапе ячейки, если есть товар: кнопка «Подробнее» или «Редактировать», ведущая на страницу товара (например `/items` с открытым редактированием по id). Усиливает связь 3D ↔ список товаров.
- **Позиция попапа в зависимости от камеры** — сейчас смещение фиксировано (`+1.2` по X). Можно вычислять смещение так, чтобы попап всегда был «справа» от ячейки в экранных координатах (или сдвигать влево/вправо в зависимости от того, с какой стороны камера), чтобы окно не уезжало за край экрана.
- **Лёгкая анимация появления попапа** — opacity 0→1 или небольшой scale за 0.15–0.2 с; создаёт ощущение отзывчивости без лишней пестроты.
- **Подсветка «подсказки» при наведении** — кроме смены цвета ячейки можно показывать над ячейкой маленький label «Ряд N, уровень M» (через drei `Html`), чтобы проще ориентироваться в большом зале.
- **Мини-карта или индикатор рядов** — компактная схема «где я на складе» (номера рядов 1–12 и текущий угол обзора или выделенный ряд). Опционально для продвинутых пользователей.
- **Полноэкранный режим 3D** — кнопка развернуть канвас на весь экран (Fullscreen API); удобно для презентаций и детального просмотра.
- **Тёмная тема для канваса** — если в приложении включена тёмная тема, подстраивать цвета пола/стеллажей/подложки под тёмный фон (или оставить светлую подложку для контраста — решить по вкусу).
