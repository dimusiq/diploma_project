# Заморозка UI на период миграции Chakra → shadcn/ui

## Статус

**Активно** на время поэтапной миграции интерфейса на стек Tailwind + shadcn/ui (см. [ADR-shadcn-ui.md](./ADR-shadcn-ui.md)).

## Правила

1. **Не добавлять новые экраны и крупные UX-потоки**, если это можно отложить до завершения миграции базовых примитивов.
2. **Не вводить новые зависимости от Chakra** в новом коде: новые компоненты — только через целевой стек (Tailwind, примитивы shadcn, `cva`, `cn()`), либо чистый HTML/CSS без Chakra.
3. **Исправления багов и a11y** в существующем Chakra-коде допускаются; по возможности выносите переиспользуемые куски в `src/components/ui/` с прицелом на последующую замену реализации.
4. **Визуальный редизайн, новые темы, новые токены** — только после согласования в рамках ADR по теме и токенам; не размножать `var(--chakra-colors-*)` в новом коде.
5. **Рефакторинг «ради красоты»** без связи с миграцией — не проводить в затронутых UI-файлах; минимальный дифф.

## Исключения

- Критические hotfix в проде.
- Изменения, напрямую блокирующие миграцию (например, вынос общего `Button` на shadcn).

## Снятие заморозки

После выполнения [Definition of Done](./CHAKRA-SHADCN-MAPPING.md#definition-of-done) и фиксации правил темы/токенов заморозка снимается командой (обновить этот файл: статус **Снята**, дата).
